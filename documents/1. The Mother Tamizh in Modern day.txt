2. PROBLEM STATEMENT & VISION
======================================================================
While modern computing continues to expand at an unprecedented pace, Tamizh 
remains largely confined to translation layers rather than existing as a native 
medium for systems-level development. 

To bridge this divide, this project does not merely aim to build wrapper scripts 
or superficial syntax translations over modern high-level languages like Python 
or JavaScript—which still fundamentally require English computing paradigms 
beneath the surface. Instead, this initiative starts strictly from extreme 
scratch:
  1. Defining a dedicated 8-bit hardware encoding standard for Tamizh tokens.
  2. Localising the GNU Assembler (gas) for native machine instruction mappings.
  3. Modifying the GNU C Compiler (GCC) backend to emit native Tamizh bytecode.
  4. Building a scalable foundation for native higher-level computing abstractions.

3. CORE ARCHITECTURAL CONSTRAINTS
======================================================================
To maintain system-level integrity and speed, all contributions must 
strictly adhere to the following technical and linguistic standards:

* High-Performance 8-Bit Encoding Matrix (128–255 Extended ASCII):
  - Do NOT introduce variable-width multi-byte UTF-8 parsing loops into the 
    core lexer states.
  - Every character token maps to a single byte (1 character = 1 byte)[cite: 2].
  - The Pulli (்) operates as a dedicated vowel-killer bridge at slot 159 (0x9F).

* Classical Senthamizh Lexicon:
  - NO Grantha letters (ஜ, ஷ, ஸ, ஹ, க்ஷ, ஸ்ரீ).
  - NO foreign or Sanskrit loanwords[cite: 2].
  - NO modern hybrid coinages[cite: 2].
  - Vocabulary must derive from attested classical roots that accurately 
    reflect the silicon-level hardware behavior of the instruction or register[cite: 2].

* Systematic Economy:
  - Every instruction and register must have a distinct, collision-free short 
    form (1 to 3 characters) designed for fast, ergonomic typing[cite: 2].
